# 🚀 Vibe Coding Study: AI 기반 퀴즈 애플리케이션

## 📌 프로젝트 개요 (Study Context)
이 프로젝트는 **'바이브 코딩(Vibe Coding)'** 패러다임을 실전 프로젝트에 적용하기 위한 스터디 과정입니다. 개발자의 직관과 AI(LLM)의 생성 능력을 결합하여, 기획부터 배포까지의 모든 과정을 AI와 협업하여 진행합니다.

## 🛠️ 기술 스택 및 환경 (Tech Stack)
- **OS:** macOS (Apple Silicon)
- **Editor/AI:** Cursor (Gemini 3.5 Sonnet / Flash), Gemini CLI
- **Language:** HTML5, CSS3, Vanilla JavaScript, Python, Markdown
- **Tools:** `npm`, `markdown-pdf`, `pandoc`, `brew`
- **Database:** GitHub Repository 내 CSV 파일 (bank_01 ~ 07.csv 및 기존 type 파일)
- **Infrastructure:** GitHub Pages (Static Hosting), GitHub REST API

## 📂 데이터 구조 및 파싱 규칙
- **CSV 통합:** Python(Pandas)을 사용하여 가상 환경(`venv`)에서 다수의 CSV를 통합 관리함.
- **Parsing Rule:** CSV의 쉼표(,) 구분자 충돌을 방지하기 위해 문장 내 모든 쉼표를 제거하거나 공백으로 대체함.
- **Dynamic Loading:** GitHub API(`https://api.github.com/repos/seohy870114/quiz_app/contents/`)를 호출하여 저장소 내 CSV 목록을 자동으로 렌더링함.

    - HTML 특화 심화 문제 (50문항): 구조, 폼, 표, 시맨틱 태그 집중 구성.
- **고도화된 해설 시스템:** 모든 문항에 대해 정답 해설뿐만 아니라 **오답 보기에 대한 상세 풀이**를 추가하여 자가 학습 품질 향상.
- **멀티 포맷 배포 체계:**
    - 마크다운 기반 문제은행 및 해설지의 PDF 변환 (`markdown-pdf` 적용).
    - 퀴즈 웹 애플리케이션(`quiz.html`) 연동용 CSV 데이터셋 7종(`bank_01~07.csv`) 생성.
- **웹 UI 확장:** `quiz.html` 내 '2026 신규 문제은행' 섹션 분리 및 신규 데이터 바인딩 완료.

### 🛠️ 기술적 구현 및 트러블슈팅
- **청킹(Chunking) 전략:** 대규모 텍스트 생성 시 발생하는 OOM(Out of Memory) 문제를 해결하기 위해 유형별, 파트별로 작업을 분할하여 생성 및 파일에 기록하는 안정적인 워크플로우 적용.
- **CSV 데이터 무결성 확보:** 질문 및 해설 내 쉼표(,)가 CSV 구분자와 충돌하는 현상을 방지하기 위해 문장 내 특수문자 정제 및 데이터 구조화 수행.
- **PDF 변환 환경 구축:** `wkhtmltopdf` 의존성 설치 문제 발생 시 `markdown-pdf` (NPM 기반) 도구로 신속히 전환하여 변환 자동화 성공.

### 💡 이번 세션 프롬프트 전략
- **단계적 구체화(Iterative Refinement):** 빠른 정답 -> 상세 해설 -> 오답 풀이 순으로 단계를 나누어 요청함으로써 결과물의 깊이를 더함.
- **데이터 일관성:** 13개 컬럼의 정교한 CSV 구조를 사전 정의하여 웹 앱과의 완벽한 호환성 확보.

- **상태 유지형 로직 구현:**
    - 문제 이동 시 기존 선택한 답안과 정오답 상태가 유지되도록 상태 객체 기반 렌더링 도입.
    - 실시간 점수 누적 방식의 오류를 해결하기 위해 전체 상태를 스캔하는 정밀 점수 집계 로직 적용.
- **프로젝트 아키텍처 독립:**
    - 공백이 포함된 경로 문제를 해결하고 배포 효율을 높이기 위해 `quiz_app` 독립 저장소로 분리 및 배포 체계 구축.

### 🛠️ 기술적 구현 및 트러블슈팅
- **Git 이력 관리 및 동기화 전략:**
    - **문제**: 로컬과 원격(GitHub)의 이력 충돌 및 `rejected` 오류 발생.
    - **해결**: `git reset --hard`를 이용한 로컬 이력의 완벽한 복구와 `git push --force`를 통한 원격 저장소 강제 동기화 기법 실습.
    - **통찰**: Git은 로컬 중심의 분산 관리 시스템임을 이해하고, `pull`과 `push`의 흐름을 명확히 파악함.
- **HTML 특수 문자 렌더링 오류 해결:**
    - **문제**: `<head>`, `<html>` 등 HTML 태그가 포함된 보기가 브라우저에서 명령어로 해석되어 화면에 미출력되는 현상 발생.
    - **해결**: `.innerHTML` 방식을 폐기하고, `.textContent` 및 `createElement` 기반의 안전한 텍스트 삽입 방식으로 DOM 조작 로직 전면 개정.
- **자동화 vs 안정성 의사결정:**
    - `config.json`을 통한 동적 로딩을 시도했으나, 빠른 배포와 실질적인 안정성을 위해 하드코딩된 안정화 버전으로 즉시 회귀(Rollback)하는 유연한 대응 전략 수립.

### 🧠 [바이브 코딩 학습 포인트]
- **데이터 바인딩의 안전성:** 사용자에게 보여주는 데이터(CSV)에 코드 형식(`<>`)이 포함될 경우, 이를 어떻게 안전하게 '문자열'로 처리할 것인가에 대한 보안 및 렌더링 원리 체득.
- **회복 탄력성(Resilience):** 코드가 망가졌을 때 `cp`를 통한 물리적 복구와 `git reset`을 통한 논리적 복구의 차이를 이해하고 상황에 맞는 최적의 도구를 선택함.
- **사용자 경험 중심의 설계:** 개발자의 편의(자동화)보다 사용자의 안정적인 접근(안정성)을 우선순위에 두는 의사결정 경험 축적.
